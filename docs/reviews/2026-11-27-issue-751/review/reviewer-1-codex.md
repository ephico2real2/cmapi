## Upstream evidence

Read on 2026-11-27. OpenShift 4.18’s release notes say “This release uses Kubernetes 1.31 with CRI-O runtime.” I checked the upstream **v1.31.0** implementation for that minor release. [Red Hat release notes](https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/pdf/release_notes/OpenShift_Container_Platform-4.18-Release_notes-en-US.pdf)

Kubernetes gates `SetDefaults_LimitRangeItem` with “`if obj.Type == v1.LimitTypeContainer`”. It fills absent defaults from max, then fills defaultRequest from default, then fills any remaining defaultRequest entries from min. Existing entries win. The generated LimitRange defaulter subsequently applies ResourceList rounding to all five maps. The quota defaulter calls “`SetDefaults_ResourceList(&in.Spec.Hard)`”. That helper executes “`val.RoundUp(milliScale)`” with scale −3. Thus `5120Mi` and `5Gi` compare equal by amount, and a planned `0.0001` in those maps is served as `1m`. [Kubernetes v1.31.0 defaulting source](https://raw.githubusercontent.com/kubernetes/kubernetes/v1.31.0/pkg/apis/core/v1/defaults.go) · [Generated call sites](https://raw.githubusercontent.com/kubernetes/kubernetes/v1.31.0/pkg/apis/core/v1/zz_generated.defaults.go)

Kubernetes declares optional arrays in the quota selector with JSON `omitempty` tags and defines its requirements as a conjunction. The fixed comparison accepts omitted empty arrays and checks each operator and value. [Kubernetes v1.31.0 API types](https://raw.githubusercontent.com/kubernetes/api/v0.31.0/core/v1/types.go)

Kubernetes says “When two or more appliers set a field to the same value, they share ownership of that field.” A dropped previous key therefore warrants a live check. For deletion, “The target object remains in a terminating state” while finalizers complete. A successful GET returning that object establishes presence. [Server-Side Apply](https://kubernetes.io/docs/reference/using-api/server-side-apply/) · [Finalizers](https://kubernetes.io/docs/concepts/overview/working-with-objects/finalizers/)

Argo CD says it “uses the `argocd.argoproj.io/tracking-id` annotation to track application resources” and documents the instance label for label tracking. Separately, “You can set the `Prune=confirm` sync option to require manual confirmation before pruning.” Those annotations share a prefix and have different owners and purposes in this folder. [Resource tracking](https://argo-cd.readthedocs.io/en/stable/user-guide/resource_tracking/) · [Sync options](https://argo-cd.readthedocs.io/en/stable/user-guide/sync-options/)

Flux documents that “`.spec.prune` is a required boolean field to enable/disable garbage collection for a Kustomization.” Its Ready condition, last attempted revision and last applied revision describe controller activity. A retained object still requires an independent read before cmapi can confirm removal. [Flux Kustomizations](https://fluxcd.io/flux/components/kustomize/kustomizations/)

## Backlog and patch decisions

- **Pre-existing apply removal defect.** Both apply paths prune documents only from paths marked deleted. Removing one ServiceAccount from a multi-document file while keeping its sibling issues no DELETE. The same worker probe observed zero deletes on all three trees. Base recorded `synced`. Head and the patch correctly timed out on the live leftover. The defect is in the existing write path, outside the PR’s changed lines. It is a separate follow-up for CRC. [Base probe](r1-outputs/base-pruner.log) · [Head probe](r1-outputs/head-pruner.log) · [Patched probe](r1-outputs/fixed-pruner.log)
- **Pre-existing reader and quantity boundaries.** The Kubernetes client maps any HTTP 404 at the object path to absence without inspecting the Kubernetes Status reason. The delete evidence assumes a genuine API-server response. The shared `tiers.qty` also predates this PR. For extremely large binary inputs, upstream `ParseQuantity` caps BinarySI at its signed 64-bit maximum, a boundary the shared parser does not implement. The patch limits its quantity change to the ResourceList defaulting relevant to this read. [Client](head/cmapi/src/cmapi/core/clients/kube.py) · [Quantity parser](head/cmapi/src/cmapi/core/tiers.py) · [Kubernetes apimachinery v0.31.0](https://raw.githubusercontent.com/kubernetes/apimachinery/v0.31.0/pkg/api/resource/quantity.go)
- **Low, presentation.** A long difference summary can crowd the optional status phrase out of a bounded wait note. The GitOps timeout event retains the structured differences and signal. The patch fixes the separate prune notice that operators need to act on.
- **Design decisions for reviewer 2.** Completing the approved grant expands D2 beyond its enumerated three kinds. Current reads add API traffic compared with D2’s cache-first approach. A poll lists accounts or bindings only when the plan or previous folder needs that kind. Helm has no hub-cluster ID in these values, so the proposed chart applies the hub containment check whenever a configured cluster selects GitOps. For an exclusively remote override this requires naming the hub identity or explicitly acknowledging its absence. Remote-cluster admission policy installation remains an operator deployment responsibility.
