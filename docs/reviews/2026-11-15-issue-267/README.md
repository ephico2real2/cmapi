# The full request flow on CRC (#267, #97)

The owner's decision of 2026-11-15, relayed on #157: run a namespace request the whole way on CRC, with the private GitHub
repository `ephico2real2/cmapi-cluster-configs`, a bot credential in a Secret, `writes: true`, and `delivery.mode: apply` with a
deliverer on the narrowest write RBAC, recorded in docs/13 and reviewed. Written by OB1 (Opus 5.5 at high). One outside model
family reviews it (Codex), since Fable is paused; the review and its decisions are added below when it is done.

## Decisions

| # | Question | Decision | Why, with sources |
|---|---|---|---|
| 1 | Which identity writes to CRC | The worker's own ServiceAccount `cmapi-worker`, bound to ClusterRole `cmapi-deliverer` | `watch_sync._deliverer` documents it as the CRC path ("the worker's own ServiceAccount on the hub"), and the chart's reviewed design binds the same (`deploy/helm/cmapi/templates/rbac.yaml`). A separate ServiceAccount would need a long-lived token Secret mounted into the same worker pod: no less reach, plus a credential that never expires. Kubernetes recommends short-lived projected tokens over token Secrets ([Service account tokens](https://kubernetes.io/docs/concepts/security/service-accounts/#authenticating-credentials)) |
| 2 | How the write is narrowed | ValidatingAdmissionPolicy `cmapi-deliverer-managed-only`, ported from the chart unchanged but for the writer and the reserved names | RBAC cannot scope `create` to a name that does not exist yet ([RBAC, Referring to resources](https://kubernetes.io/docs/reference/access-authn-authz/rbac/#referring-to-resources): "You cannot restrict deletecollection or top-level create requests by resource name"). A policy matched on the worker's username keeps it to namespaces labelled `cmapi.net/managed=true`, read from the old object on an update. GA in Kubernetes 1.30 ([Validating Admission Policy](https://kubernetes.io/docs/reference/access-authn-authz/validating-admission-policy/)); CRC serves `admissionregistration.k8s.io/v1` (Kubernetes v1.35.6, read with `oc api-resources`). `test_crc_deliverer_is_the_charts` holds the two equal |
| 3 | `create` as well as `patch` | Both, as the chart has | "a principal ... requires the patch permission to edit existing resources, and also needs the create verb permission in order to create new resources with Server-Side Apply" ([Server-Side Apply, Access control and permissions](https://kubernetes.io/docs/reference/using-api/server-side-apply/#rbac-and-permissions)) |
| 4 | ClusterRole `cmapi-token-issuer` | Not created. `bind` on its name stays | Each rendered folder binds it for the sa-tokens plugin, which cmapi does not have (no `plugins/sa_tokens`). "You can only create/update a role binding if you already have all the permissions contained in the referenced role ... or if you have been authorized to perform the `bind` verb on the referenced role" ([RBAC, Restrictions on role binding creation or update](https://kubernetes.io/docs/reference/access-authn-authz/rbac/#restrictions-on-role-binding-creation-or-update)). So the binding can be written, and it grants nothing until a later pull request adds the role. Least privilege: no unused grant. The page does not say whether the role must exist; Kubernetes' RoleBinding storage checks `bind` before it reads the role (inferred from its source, not measured), and the first delivered namespace on CRC is the proof |
| 5 | The Git host's trust (#97) | `CMAPI_GIT_CA_BUNDLE`, an explicit `ssl.SSLContext` from that file alone; unset, today's trust | httpx 0.28.1 reads `SSL_CERT_FILE` for `verify=True` (`httpx/_config.py`, `create_ssl_context`, lines 33 to 40), and the pods set it to cmapi-trust, Keycloak's CA alone. An explicit context is the only trust no environment variable changes. A site whose private Git host is in `CMAPI_CA_BUNDLE` keeps working. A missing file stops the process at start |
| 6 | Which bundle on CRC | `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`, the image's system trust | RHEL's shared system certificates (`update-ca-trust(8)`; [RHEL 9, Using shared system certificates](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/securing_networks/using-shared-system-certificates_securing-networks)): updated with the base image's `ca-certificates`, and where a site adds an enterprise CA. certifi would work too, but is pinned by pip and not where an operator looks. The image's own build stage fetches from github.com with the same base image's trust (`cmapi/Containerfile`), which is evidence by construction, not a measurement in the pod |
| 7 | The bot's credential | A fine-grained personal access token, in Secret `cmapi-git`, key `token`, made by the owner from stdin | The code sends one static Bearer token (`HostGitProvider._headers`; `settings.git_token`) and has no GitHub App token minting: an installation token lasts one hour ([GitHub, Authenticating as a GitHub App installation](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation)). Scoped to the one repository, with Contents, Pull requests and Commit statuses read and write, Checks and Metadata read, each what `core/git/github.py` calls |
| 8 | The config repository's checks | A workflow with jobs `ci/kubeconform` and `ci/kyverno`, and `kyverno_check.py`; template and tests in `examples/cluster-configs/.github/` | `GitHubProvider.external_ci` makes `pr_checks` wait for those two check runs. A job's check run takes the job's name: measured on `cmapi-cluster-configs` pull request 1 (`logs/ccc-pr1-check-runs.txt` in the run record). The mode is read from each rendered policy's `validationActions`, so the bundle carries it. cmapi's ratchet is not reproduced, said in the script |
| 9 | Branch protection | None: the free plan refuses it (#227) | Said in docs/13 and the repository's README, with what holds instead: the bot, `cmapi/check`, the main-equals-plan check before an apply, and the admission policy |
| 10 | Rollback | Stops, deleting nothing, while a namespace labelled `cmapi.net/managed=true` exists; removes the worker's write before its containment, and `cmapi-git`, by name | A delivered namespace is a team's, and the rollback deletes nothing it cannot name. The read with a selector is a read, never a delete |
