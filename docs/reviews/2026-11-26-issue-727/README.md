# OpenShift 4.18 and later: the audit of every OpenShift-specific dependency (#727)

The owner, 2026-11-26: "We need to make sure that this kind work in openshift 4.18 and above", then "We dont have openshift
4.18 in our lab but my ask is that to look at the documentations." So this audit is documentation and source only. Every
4.18 statement below comes from `openshift/openshift-docs` branch `enterprise-4.18` or an `openshift/*` repository at
`release-4.18`. Each one is compared with the newest branch that exists: `release-4.23` for the source repositories, and
`enterprise-4.22` for openshift-docs, which has no `enterprise-4.23` branch yet. The only cluster cmapi has run on is CRC
4.22.14 (Kubernetes v1.35.6, `oc version`, read 2026-11-26). Nothing here was run on 4.18.

Every source was fetched on 2026-11-26 with `gh api repos/<org>/<repo>/contents/<path>?ref=<ref>`. The commit of each ref is
listed in [Sources](#sources). The only CRC reads were the read-only `oc get` commands quoted in the rows.

## Result

cmapi's OpenShift-specific dependencies are the same on `release-4.18` and on the newest branch, for everything cmapi uses.
Three things differ between the releases, and none of them needs a code change:

1. **Direct authentication.** The `ExternalOIDC` gate is TechPreview on 4.18 and on by default on 4.23. With direct
   authentication, `*.user.openshift.io` is not served. cmapi already falls back to a SelfSubjectReview. This pull request adds
   the test that holds that path (row 9).
2. **CloudNativePG and Kyverno.** Their own support ranges do not span 4.18 to 4.23. These are operators that the site
   installs, not part of OpenShift. docs/13 and docs/18 now say which version goes with which release (rows 17 and 18).
3. **NetworkPolicies in OpenShift's own namespaces.** These are new in 4.22. 4.18 has none. The ones on the newest releases
   allow what cmapi needs, and CRC 4.22.14 runs cmapi with them (row 3).

One statement in cmapi was wrong, and is now corrected. The front door's NetworkPolicy comment said that a host-network
router on another node "would need a peer for policy-group.network.openshift.io/host-network". **I retract that statement:
the source refutes it** (row 2). It was marked "Inferred" in the PR #89 review.

## What was fixed in this pull request

- **Row 2, the comment.** `deploy/manifests/components/cmapi/40-networkpolicy.yaml` said that a host-network router on
  another node needs a second peer. It now says why the one peer matches it, with this record as the source. The policy itself
  does not change. `test_only_the_router_reaches_the_front_door` (plain) and `test_only_the_front_door_reaches_the_api_port`
  (chart) already require the peer to be exactly this one, with no `podSelector`.
- **Row 9, the test.** `cmapi/tests/service/test_registry_survives_419.py` gains
  `test_an_openshift_cluster_with_direct_authentication_is_identified_by_selfsubjectreview`. The handler answers users/~
  with 404 and the SelfSubjectReview with the reader. The cluster is `connected`, and the calls are exactly `/version`,
  users/~, the review and the namespace list. It passes on `main`'s code, because the behaviour was already right. A mutant
  of `KubeClient.whoami` that raises on a non-200 instead of falling back makes it fail (run on 2026-11-26).
- **Rows 17 and 18, the support statement.** docs/13 and docs/18 now state "OpenShift 4.18 and later", link here, and say
  which CloudNativePG release and which Kyverno release go with which OpenShift release.

## Unknown

- **CloudNativePG 1.31 or later**, which 4.23 needs (row 17). Its bundle covers v4.20 to v5.0, so it is not offered on
  4.18. cmapi's `Cluster` has been run on 1.30.1 only (kind and CRC). Whether 1.31 accepts it unchanged was not tested, and
  1.31 is a release candidate (`1.31.0-rc1`).
- **OpenShift 4.23 itself.** Its branches exist in the source repositories, but openshift-docs has no `enterprise-4.23`
  branch, so the documentation of 4.23 was not read. The newest documentation read is 4.22.
- **4.19, 4.20 and 4.21.** Only the two ends were compared. A dependency that changed in a middle release and changed back
  would be missed. For each row the same text is on both ends, so no such change is expected, but none was read.
- **A live run on 4.18.** None was made. The owner's lab has no 4.18 (2026-11-26).
