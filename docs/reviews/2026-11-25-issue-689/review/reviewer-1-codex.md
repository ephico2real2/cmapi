**Request changes on head `d692adc`.** The 39 authenticated contract operations charge the correct caller bucket, and #694 works for the retry-bearing problem types. The [proposed patch](r1-outputs/fix.diff) applies from the repository root with `patch -p1 -F0`. ## Answers to the brief

1. **Coverage.** I dispatched each committed operation, recorded every `take(kind, sub)` call, and checked the sequence against an independent expectation. All 39 protected operations charged once for the verified subject on head and fix. There are 22 reads, 15 writes, one suggest and one export. All 24 protected GETs charged the same class through HEAD. The public version GET and HEAD charged zero. Each other action falls under its verb unless the template selects a named class. The future `:place` has a class test only. Health, readiness, problem pages, public docs and the OAuth redirect had zero caller debits. Private docs are the exception in the findings. [Method and template inventory](r1-outputs/operations.txt)
2. **Order.** On valid JSON, the trace was decode → authenticate → caller charge → schema validation. A bad token with decodable JSON yielded 401 and zero charges. Malformed JSON yielded 422 before authentication. A caller over quota with a syntactically valid, schema-invalid body got 429. The original seven-run probe measured medians of **0.029 s** for JSON decode, **0.033 s** for 429 and **0.427 s** for 422 on 769,136 bytes. That supports the README’s explanation of its 0.030 s result. Unauthenticated requests can still consume body-read, decode and authentication CPU. #683 bounds each body and the validation response. Neither that bound nor a post-authentication bucket caps the aggregate rate of unauthenticated traffic. [Protocol checks](r1-outputs/protocol.txt) · [Timing](r1-outputs/protocol-and-timing.txt)
3. **Team.** The token carries a subject but no trusted team membership. Creation accepts an authorized caller’s permitted namespace label. The existing service test submits successful creates for different named teams as the same caller. Namespaces without a team have no team bucket. Those are design properties. Independent caller write limits still apply, and an operator can configure a team budget smaller than a single caller’s budget. Updates merge request labels over Git. Deletes read their team from Git. The patch uses the already-held team for changes to a labeled namespace. Dry runs, refused plans and ordinary replays skip team charging. Head’s failure and racing-replay exceptions are covered above. Team admission follows Git reads, rendering and validation, so it protects request persistence and subsequent worker activity. The tested refusal path issued no change-request DML or Git writes after the fix. Authentication can independently persist refreshed JWKS before any caller or team decision (`Jwks._refresh` path and `DbKeyStore.save`).
4. **Concurrency and memory.** Head’s synchronous `take` reads the monotonic clock, refills, debits and updates refusal state within one process-local `threading.Lock`. There is no await in that section. This covers the async dependency and threadpool submitters. Thirty-two concurrent attempts against a frozen seven-token burst admitted seven, and exactly one refusal was marked first. Head’s cardinality claim failed separately. On the patch, transaction I/O uses a separate team reservation lock and leaves the caller accounting lock available. A replica restart refills local budgets, and separate replicas have independent caller and team quotas as designed.
5. **Clock and wire values.** The clock defaults to `time.monotonic`. The controlled-clock tests exhaust a burst, retry without spending tokens, advance a partial period, then cross the refill boundary. Ordinary refusals round a positive wait up to whole seconds, with the same integer in the JSON extension and decimal header. The extreme valid-rate exception is fixed above. A zero delay is valid HTTP syntax but would be incorrect for this positive remaining wait. The zero-header mutant failed on exactly that discrepancy.
6. **Config and defaults.** Instance validation runs at load. Each omitted class or field takes a positive per-replica default. The defaults in calls/minute and burst are read 120/60, write 60/30, place 10/5, suggest 240/40, export 4/2 and team 600/200. They bound normal traffic without an off switch. Production capacity sizing remains site-specific. The schema and parser cap both numbers at 2⁵³−1. Unknown classes and fields, nonpositive rates, zero or fractional bursts, booleans and over-limit numbers are rejected. The original Helm test rendered real values, and the additional test exercises exponent notation. The four #693 imports passed in fresh interpreters with both optional packages blocked. [Head matrix](r1-outputs/config-head.txt) · [Isolated import and core tests](r1-outputs/head-focused-core.txt)
7. **#694.** Confirmed on head. The real JWKS failure path returned 503 with 30 in both places. I also sent `idp-unavailable`, `cluster-unreachable`, `validator-unavailable` and `rate-limited` through the installed exception handler. Each retry-bearing problem sent the matching header. `docs-assets-missing` (503), `git-unavailable` (502) and `unauthenticated` (401) omitted it. Current producers supply positive integers. The contract marks the header required when all documented problem examples carry it and conditional when only some do. [Protocol assertions](r1-outputs/protocol-check.py)
8. **Test sensitivity.** The unmodified new files on base fail at collection for absent `SWEEP_AT` and `RATE_LIMITED`. I also ran the implementer’s stand-in service file on a head-test copy with base `src`: 17 failed, two passed. Its copied class selector and ordinary replay guard account for the passes. On unmodified head all 19 service cases passed with the substitute database. The unchanged service assertions killed all four mutants independently. ## Sources checked on 2026-11-25

- RFC 6585 §4 (April 2012) permits “a Retry-After header indicating how long to wait before making a new request.” It also forbids caching a 429. [RFC 6585](https://www.rfc-editor.org/rfc/rfc6585.txt)
- RFC 9110 §10.2.3 (June 2022) specifies “A delay-seconds value is a non-negative decimal integer, representing time in seconds.” The field also applies to a 503 indicating expected unavailability. [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.txt)
- The IETF datatracker lists revision 12, dated 2026-11-20, as a “WG Document” with IESG state “I-D Exists.” It expires 2027-05-24. Using the standardized Retry-After field alone is consistent with this PR’s design. [RateLimit header fields for HTTP](https://datatracker.ietf.org/doc/draft-ietf-httpapi-ratelimit-headers/)
- OWASP API4:2023 recommends “Implement a limit on how often a client can interact with the API within a defined timeframe (rate limiting).” Endpoint-specific budgets implement that recommendation. [OWASP API4:2023](https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/)
- FastAPI 0.162.2 reads `json_body = await request.json()` before `solved_result = await solve_dependencies(`. The solver iterates `for sub_dependant in dependant.dependencies:` before `await request_body_to_args(`. The installed wheel has the JSON reads at lines 464/471, dependency solving at 511, and body validation at 762 in the solver. [FastAPI routing source](https://raw.githubusercontent.com/fastapi/fastapi/0.162.2/fastapi/routing.py) · [Dependency solver](https://raw.githubusercontent.com/fastapi/fastapi/0.162.2/fastapi/dependencies/utils.py)
- Starlette 1.10.0’s request implementation executes `body = await self.body()` and `self._json = json.loads(body)`. That decode is synchronous. [Starlette request source](https://raw.githubusercontent.com/Kludex/starlette/1.10.0/starlette/requests.py) · [Installed versions and source lines](r1-outputs/framework.txt)
