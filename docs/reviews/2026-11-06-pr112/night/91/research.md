# TLS choice for issue #91

READ FROM CODE — Keep the WIP design: `PGSSLMODE=verify-full` and `PGSSLROOTCERT=/etc/cmapi/ca/database-ca.crt` on api, worker and both migrate initContainers. Project only `ca.crt` from `cmapi-db-ca`, beside the separate HTTP trust bundle. Do not copy credentials into another Secret or rewrite the operator-owned URI. CNPG's generated `uri` carries no TLS parameters; these libpq defaults supply them. Explicit URI parameters take precedence, preserving docs/12.

READ FROM CODE — Options: `prefer` permits plaintext; `require` requires encryption but has conditional CA verification and no hostname check; `verify-ca` checks the chain but not the hostname; `verify-full` checks both and rejects untrusted servers. Merely setting a CA cannot make `prefer` safe. PostgreSQL recommends explicit verification modes. [PostgreSQL 16 SSL support](https://www.postgresql.org/docs/16/libpq-ssl.html).

READ FROM CODE — `sslrootcert` selects the PEM trust file. Environment variables supply defaults when the caller did not specify a value. A URI naming `sslmode=verify-full&sslrootcert=/etc/cmapi/ca/ca-bundle.crt` therefore retains its external-server trust. These are defaults, not a policy against an administrator deliberately specifying weaker URI options. [Connection parameters](https://www.postgresql.org/docs/16/libpq-connect.html#LIBPQ-CONNECT-SSLROOTCERT), [environment variables](https://www.postgresql.org/docs/16/libpq-envars.html).

READ FROM CODE — CNPG's operator-managed CA Secret contains public `ca.crt` and signing key `ca.key`; only the certificate belongs in clients. CNPG renews managed certificates automatically. Its own internal use of CA-only verification is not a recommendation to skip hostname verification in this application. [CNPG 1.30 certificates](https://cloudnative-pg.io/docs/1.30/certificates/).

READ FROM CODE — A dedicated CA file restricts database trust to this cluster; appending the CA to the HTTP bundle unnecessarily broadens trust and requires copying/refreshing it. An initContainer copy would become stale; projecting the Secret directory receives kubelet updates. No subPath is used. [Kubernetes Secret volume updates](https://kubernetes.io/docs/concepts/configuration/secret/#using-secrets-as-files-from-a-pod).

READ FROM CODE — The projection is optional only to allow the supported external deployment, which has no CNPG Secret. For the default URI, verify-full still requires the file; its absence or invalid contents must fail closed. Making this shared projection required would break docs/12 before libpq could use the external CA. No fallback CA path is selected by application code.

READ FROM CODE — CNPG v1.30.1 `renewCASecret` updates `ca.crt` in the same Secret using the existing private key. Kubelet eventually refreshes the directory projection; each new libpq connection reads the path. Nothing in this change restarts api/worker on CA updates: `checksum/config` hashes only the three ConfigMaps. Existing TLS sessions continue; an arbitrary out-of-band CA key replacement can cause transient connection failures while projection/server updates converge. This fails closed, and is not a measured zero-downtime key rotation guarantee. [CNPG renewal implementation](https://github.com/cloudnative-pg/cloudnative-pg/blob/v1.30.1/internal/controller/cluster_pki.go#L188).

PROPOSAL NOT OPERATED — Real CNPG certificate contents, successful TLS sessions, bad-CA refusal, projection refresh, and external TLS operation need the coordinator's kind run. No PostgreSQL or cluster was contacted here.

READ FROM CODE — CNPG v1.30.1 builds `uri` using service plus namespace: here `cmapi-db-rw.cmapi` (not the `.svc` name used by the DNS diagnostic). Its generated server SANs include service alone, service.namespace, service.namespace.svc and the full cluster-domain name. Thus the URI host is covered without custom SANs. [URI generation](https://github.com/cloudnative-pg/cloudnative-pg/blob/v1.30.1/pkg/specs/secrets.go#L40), [GetClusterAltDNSNames](https://github.com/cloudnative-pg/cloudnative-pg/blob/v1.30.1/api/v1/cluster_funcs.go#L1046), [certificate documentation](https://cloudnative-pg.io/docs/1.30/certificates/#server-alternative-dns-names). The Cluster does not override certificate configuration. Live SAN inspection is still NOT REACHED.
