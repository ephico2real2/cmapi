**PostgreSQL was unreachable.** Both exports reached the service suite's migration fixture and failed with `127.0.0.1:55432 failed: Operation not permitted`. The database-backed API, approval ledger, locking and worker transactions still need reviewer 2's PostgreSQL run. No SQLite was used.

**Request changes.** Head can send an unconditional Kubernetes write after checking the approved UID. Its approval rules also allow configurations that satisfy an adoption without the required people. In the focused comparison, head failed 19 checks and passed 24. The patched copy passed all 43. The patch applies cleanly to the supplied head and reproduces all 17 changed files byte for byte. ## Backlog and design boundaries

- **Argo CD's last-read interval remains open.** D16 says “The time between the last read and the sync is not covered”. Git carries the cleaned manifest without its Kubernetes UID or resource version. The Argo path observes a controller operating after merge. The worker cannot enforce its own conditional write on that controller. Section 0 also defers B4's exact post-sync comparison and B6's shared-resource protection. A universal claim that every delivery mode takes over only the approved UID exceeds this design. [D16 and built scope](head/docs/reviews/2026-11-14-issue-26-adoption/README.md) · [Sync observer](head/cmapi/src/cmapi/jobs/watch_sync.py)
- **Ordinary create and apply already trust the managed label.** On both base and head the create guard rejects a present unmarked Namespace with 409, but accepts the managed marker as ownership evidence. An ordinary PATCH needs a Namespace manifest in Git. Base's direct worker already separates its ownership read from a forced apply. A marker change or replacement during that interval is therefore a pre-existing limitation of “never a silent takeover”. The scoped patch preserves the ordinary path. The seven shared controls cover the marker, the missing Git folder, and single, multiple and tier-rendered quota selection. [Base naming guard](base/cmapi/src/cmapi/core/naming.py) · [Base apply](base/cmapi/src/cmapi/jobs/apply.py) · [Base planner](base/cmapi/src/cmapi/core/pipeline.py)
- **External GitHub CI has a separate enforcement limitation.** The example workflow script already says “Not done here: cmapi's ratchet”. Its enforce check can refuse a held value that the internal worker accepts using the approved snapshot. This affects end-to-end delivery on hosts requiring that external check. I found no PR-file source for the internal policy base. The pinned Kyverno CLI was unavailable locally, so no real CLI enforcement result is claimed. [Existing external check](base/examples/cluster-configs/.github/scripts/kyverno_check.py) · [Internal validator](head/cmapi/src/cmapi/core/validate/__init__.py)
- **Quota editing and post-sync proof remain bounded by section 0.** B3's general in-place edit of a named adopted object is deferred. The existing `confirmed_by_read` checks Namespace presence and planned quota hard values. It does not prove all original child fields, metadata or field-manager ownership survived a real sync. [Built and deferred work](head/docs/reviews/2026-11-14-issue-26-adoption/README.md) · [Read confirmation](head/cmapi/src/cmapi/core/sync.py)
- **Low · Portal copy assumes the default selector value.** The candidate header can show a configured label name while displaying the literal value `"true"`. The selection logic accepts a configured value. [Portal copy](head/cmapi-portal-ui/src/portal/AdoptView.tsx) · [Selector configuration](head/cmapi/src/cmapi/core/adoption.py)
