## Sources read on 2026-11-25

- Prometheus documents “GET /api/v1/query” and “GET /api/v1/query_range”. For `warnings` it says “Only set if there were warnings while executing the request.” A successful response may include both data and warnings. This implementation needs one instant vector per expression at a common timestamp. Its PromQL subqueries describe the windows. A range request would evaluate the expression repeatedly between start and end. [Prometheus HTTP API](https://prometheus.io/docs/prometheus/latest/querying/api/)
- Thanos says “If partial response happen QueryAPI returns human readable warnings”. Its API also documents deduplication, the `partial_response` parameter and warnings in query data. The client asks for deduplication and disables partial responses. The parser must still check warnings. [Thanos Querier](https://thanos.io/tip/components/query.md/#query-api-overview)
- Docs/01 specifies “Once per quota-change plan, cached 10 minutes” and says “the change needs a platform approval instead of failing”. The storage column for those figures says “No”. [Design lines 418 and 451](https://github.com/ephico2real2/cmapi/blob/8ceea45/docs/01-design-and-architecture.md#L418-L451)
- Docs/02 specifies “the cmapi-reader token bound to cluster-monitoring-view” and “a 10-second timeout”. It permits embedded collection and describes a dated result after a missed sweep. [Capacity plugin](https://github.com/ephico2real2/cmapi/blob/8ceea45/docs/02-technical-design-v2.md#L1383-L1420) · [Embedded mode and failure behavior](https://github.com/ephico2real2/cmapi/blob/8ceea45/docs/02-technical-design-v2.md#L1484-L1490)
- Docs/03 requires “at least 80% of the window's steps” and says “A failed or warned query gives that cluster's namespaces insufficient-data for the day”. Its verdict table gives inclusive tight thresholds and strict waste thresholds. [Collection, accuracy and verdicts](https://github.com/ephico2real2/cmapi/blob/8ceea45/docs/03-usage-analysis.md#L44-L103)

## Conclusions on the seven requested checks

1. **Thanos security.** The registry builds the cluster reader from the imported Secret’s token, checks the reported ServiceAccount identity before adopting the client, and monitoring copies that reader’s Authorization header. The baseline binds `cmapi-system/cmapi-reader` to `cluster-monitoring-view` and permits getting the named Querier Route. It is the designed read identity, shared with other cluster reads and scoped reader renewal. Actual privileges of a site’s imported token cannot be inferred from the YAML. The fixed monitoring client uses the project CA store even if API trust is insecure. No live credentials or endpoints were needed for testing. The public planner rejected the invalid namespace with 404, and the quota list rejected the invalid verdict with 422. Cluster ID selects a registry client and endpoint. List filters never enter PromQL.
2. **Approvals and cache.** All seven standalone rules files and both rendered ConfigMaps contain the same platform increment. An independent 540-case comparison of the actual base and head engines/configs covered normal, critical and temporary names, the served environments, three increase values and all three usage states. Head preserved base slots in every case, with one extra platform slot for unavailable. With shipped rules a failed read can replace a ratio-based platform slot with the outage slot, or add one if the ratio rule would not fire. The caller cannot supply the usage state or Thanos destination in the request. A cached answer deliberately masks a new outage through second 599. On expiry a failure is visible and the next plan retries. A clean but thin vector produces insufficient data under the agreed policy.
3. **Verdicts.** The 4,032-step window requires 3,226 integer samples. At exactly 0.8 the decision is sufficient. The original tests exercise 10% versus 9.99% of hours, exhaustion at 1.0, equality at the environment’s waste floor, and CPU or memory equality at the idle cutoff. The five environment mappings, enabled verdicts, headline precedence and missing history are covered. A warning fails the whole cluster read and the sweep emits dated insufficient-data verdicts. The live path marks that same failed query unavailable. The fake checks generated query text and supplied numeric results. It is not a PromQL evaluator or evidence about an installed Thanos.
4. **Migration and two workers.** Offline Alembic SQL for 0009 → 0010 and its reverse creates and drops the two new tables, their checks and indexes, and updates the revision marker. There is no 0010 DML against 0009 application rows. Full-chain offline generation reaches 0009’s data-dependent query, which requires a connection. The PostgreSQL tests for empty-schema up/down/up, historical-row preservation, Alembic/model parity and concurrent job claims all stopped at the connection attempt. Empty-database round trips and populated-0009 preservation remain unverified. The worker follows the existing pattern: the pending-job unique index coalesces null request and payload-kind values, claims use `FOR UPDATE SKIP LOCKED`, and a generation check fences the handler transaction before commit. Finishing a job and enqueuing its successor share that transaction. The worker stops renewing a lease after its existing 30-minute handler limit. A reclaimed lease can duplicate a long-running read. The fence should roll back stale writes. This is a source conclusion, not a two-process run or query-plan measurement.
5. **Quota API.** A configured list request adds **one verdict query**. Row assembly executes **two SQL statements in total**, including the pre-existing open-request query. The verdict query joins against the latest sweep day per cluster. In a 32-row fixture using the route function and a recording session, the count stayed at two, filtering selected the requested headline, and severity put tight before idle. The route scopes rows before returning them and uses the shared name/cluster tie-break. The patched disabled path skips the verdict query. `oasdiff breaking` from base to head exited 0. The portal’s generated API-type check agreed with the checked-in contract.
6. **Portal.** The verdict and single-resource suffix, dated explanation, attention chips and severity-positive count use API fields. Null measurements render as dashes while known quotas remain visible. The mockup differences include a separate insufficient-data pill, CPU as a possible single-resource suffix, the extra tier-outdated chip, daily timing without a fixed hour, and deferred recommendations. An isolated React render used the production formatting functions and captured both table rows. It verified the values, units, quota transitions, reasons and footnote for all three live states. `npm test` passed contract/type checks, TypeScript, both Vite builds and 44 direct tests, then Chromium’s sandbox startup stopped the run. Browser interaction, visual fidelity and viewport checks remain unverified in this environment.
7. **Tests discriminate.** The new core and service files copied into a base-source tree both failed collection because base lacks `cmapi.capacity`. The original 38 focused head core tests passed. The final reviewer core tests produced **28 failures and 4 passes on head**. All **70 focused core tests passed** on the freshly patched copy, and the planner service regression passed there without a database. The original head service/list command with the database startup wait shortened returned 1 pass and 12 database setup errors. The original full head core run had five Go-cache permission failures. All five passed when rerun with a writable cache inside the review directory.
