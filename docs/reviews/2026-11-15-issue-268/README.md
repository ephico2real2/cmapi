# Issue #268: the backup's checks read the dump to its end

**The defect.** The first CRC run stopped at docs/13 step 13 on 2026-11-15T01:50Z (main 9407d8e4dd): `error executing command in container: write |1: broken pipe`, then `pg_restore --list refused the archive`. Nothing reached Keycloak; keycloak-0 and postgres-0 kept 0 restarts.

**Measured cause.** `deploy/crc-backup.sh` streams the dump into `oc exec -i postgres-0 -- sh -c '<check>'`. On PostgreSQL 16, with a 2,970,565-byte custom-format dump on stdin, `pg_restore --list` read 2,052 bytes and exited with rc 0, leaving 2,968,513 unread (`pg_restore --list >/dev/null; wc -c` in one exec). `pg_restore -a -t realm -f -` stops after realm's data block, so it leaves unread every table whose data follows realm's in the archive's name order: on the test's dump, 592,037 bytes with `user_entity` after `realm`, and none while realm's data was the archive's last (measured, podman, PostgreSQL 16.15). `pg_restore -f /dev/null` read it all. The shared Keycloak database is 14 MB, so its dump is far past a 64 KiB pipe buffer, and CRI-O's exec reports the stdin it could not write as an error, so `oc exec` exits non-zero (that the threshold is the pipe buffer is inferred: CRC ran only the 14 MB database). Podman 5.5.2's exec leaves the same stdin unread, prints `Error: write unixpacket @->/proc/self/fd/15/attach: write: connection reset by peer` and still exits 0 (6 of 6 runs), which is why `deploy/tests/crc-backup-test.sh` passed; the stub in `crc-scripts-test.sh` drains stdin itself.

**Options.**
1. Drain stdin in the pod after each check, keeping the check's own status. Chosen: it fixes the cause (the exec stream must be consumed), keeps every check as it was, and writes nothing in the pod.
2. Read the archive once with `pg_restore -f -` and derive the count and the realm rows from that stream. Rejected: it rewrites three checks into one parser of pg_restore's SQL output, a larger change for the same result.
3. Copy the file into the pod and run `pg_restore --list` on a seekable file. Rejected: docs/13 holds that nothing is written in the pod.

**The test.** `crc-backup-test.sh`'s `oc` stand-in now fails an `exec -i` whose command leaves any stdin unread, as CRI-O does past the buffer (stricter: any byte), and the seed data makes a dump past 64 KiB (641,305 bytes, asserted). Its random-data table is named `user_entity`, Keycloak's own, which sorts after `realm`, so `--list` and `-t realm` each leave more than 64 KiB unread (asserted, by `wc -c` after each), as on Keycloak's database, and a cut tail is caught only by the full read: the two cut-stream cases assert that check's message. Before the fix, on 9407d8e's `deploy/`: 13 cases fail, the first with CRC's own message, `pg_restore --list refused the archive`. After: 0 fail. With `-f /dev/null` removed, the cut-stream cases fail (4); with the realm count left undrained, 11 fail. Logs: `ob1-run8/logs/268-backup-test-before.log`, `268-backup-test-after.log` in the run's workbench.

**Sources.** pg_restore's documentation: with no file name the archive is read from standard input, and `-l` lists the table of contents (https://www.postgresql.org/docs/16/app-pgrestore.html). Kubernetes #112834 on exec's stdin stream and its close ordering (https://github.com/kubernetes/kubernetes/issues/112834). The read sizes above are this run's measurements.
